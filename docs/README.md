# OctoAcme Project Management Docs

A guide to the processes, roles, and practices OctoAcme uses to deliver cross-functional projects.

## Project management processes summary

OctoAcme begins by validating a project’s business need, outcomes, stakeholders, and initial risks. Once approved, the team plans scope, estimates and prioritizes backlog work, defines acceptance criteria and the Definition of Done, and maps dependencies and milestones. During execution, teams track work on a project board, review progress and blockers regularly, test and review changes, and escalate risks through the agreed channels. Releases require acceptance criteria, passing CI and security checks, release notes, smoke tests, and a rollback plan. After sprints, releases, milestones, or incidents, teams capture lessons and track a small set of actionable improvements. PMs coordinate delivery, risks, and communications; Product Managers own outcomes and priorities; developers and QA deliver and validate the work with stakeholder input.

## How to use these docs

Use this folder as the entry point for OctoAcme’s project management process. Start with the overview to understand the lifecycle, then move into the initiation and planning guidance when a project is being defined. Use the execution, risk, and release documents during delivery to keep the team aligned on quality and operational readiness. Consult the retrospective and role docs when improving team practices or onboarding new teammates.
